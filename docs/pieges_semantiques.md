# Pièges sémantiques Dataiku → Databricks

Repris de la section « Pièges sémantiques » de `ROADMAP.md`. Chaque piège doit avoir **au moins un test** et une règle dans le traducteur concerné. La colonne « Test » sera remplie au fil des phases.

| Piège | Dataiku | Databricks / Spark | Règle | Phase | Test |
|---|---|---|---|---|---|
| Chaîne vide et NULL | `isBlank`, `FillEmptyWithValue` et `coalesce` traitent `''` comme vide | `coalesce` ne remplace que NULL | Générer `coalesce(nullif(col, ''), valeur)` ou l'équivalent | 4 | **fait** : formules `isBlank`, `isNonBlank`, `coalesce` (`test_blank_means_null_or_empty_string`) et processeur `FillEmptyWithValue` (`test_demo_simple_prepare_runs_on_spark`) |
| Arrondi des négatifs | Documenté : `round(-3.5) = -3` | `round` en HALF_UP : `-4` | `FLOOR(x + 0.5)` (et `FLOOR(x * 10^n + 0.5) / 10^n` avec des décimales) | 4 | **fait** : `test_round_half_up_including_negatives` (PySpark) |
| Concaténation avec `+` | Concatène des chaînes (moteur DSS) | Addition numérique | `\|\|` dès qu'un côté est une chaîne (typage des expressions) ; NULL propagé (H-46, à vérifier) | 4 | **fait** : `test_plus_concatenates_with_a_string` |
| Dates et fuseau | Dates locales selon la configuration | Références de job en UTC | Date de partition calculée dans un fuseau explicite (`timezone`, défaut `Europe/Paris`) : `CURRENT_TIMESTAMP` converti avant d'en prendre la date ; planification avec le fuseau du scénario | 4–6 | **fait** : `test_date_parser_on_spark_with_paris_time`, `test_partition_date_uses_the_job_time_zone`, `test_scenario_becomes_a_scheduled_job_of_its_steps` |
| Patterns de date | `SimpleDateFormat` (Java) | Patterns Spark (`DateTimeFormatter`) : `Y`, `u`, `S`, noms et fuseaux diffèrent | Table de conversion limitée aux lettres de même sens (`MM` mois, `mm` minutes…) ; le reste est refusé | 4 | **fait** : `test_pattern_table`, `test_patterns_never_guess` |
| Fuzzy join | Damerau-Levenshtein (transposition = 1) | `levenshtein` simple (transposition = 2) | Classer `LLM_REVIEW` ou `MANUAL`, recalibrer les seuils | 3 | à faire |
| Top N à égalité | Ordre non déterministe | Idem | Ajouter une colonne de départage | 3 | **fait** : départage par les autres colonnes de l'entrée, avec avertissement (`test_first_rows_with_a_deterministic_tie_break`) |
| Distances géographiques | — | `st_distance` est planaire (degrés) | Utiliser `st_distancesphere` pour des mètres | 4 | à faire |
| Typage | « Meanings » et inférence Dataiku | Types Spark stricts | Utiliser le schéma déclaré dans l'export, avec un `cast` explicite | 3–4 | à faire |
| Steps Prepare groupées | `metaType` différent de `PROCESSOR` | — | Lever une erreur, ne jamais filtrer en silence | 4 | **fait** : les groupes (`GROUP`) sont traités explicitement (un groupe désactivé désactive ses étapes, listées) ; tout autre `metaType` lève `UnsupportedConstruct` (`test_disabled_group_skips_its_steps`, `test_prepare_never_guesses`) |
| Variables dans les noms de tables | `${projectKey}`, `${NODE_DC}` | — | Résoudre, sinon signaler | 1 | **fait** : `test_variables_resolved_in_table_names`, `test_unresolved_variable_is_listed` (`tests/test_reader.py`) et `tests/test_variables.py` |
| Échantillon « premières lignes » | `HEAD_SEQUENTIAL` : les N premières lignes dans l'ordre de stockage | `LIMIT N` sans ordre : lignes quelconques | Traduire en `LIMIT N` **avec un avertissement** dans l'en-tête et le rapport ; l'échantillonnage aléatoire lève `UnsupportedConstruct` | 3 | **fait** : `test_head_sampling_is_a_limit_with_a_warning`, `test_sampling_never_guesses` (`tests/test_translate_sync.py`) |
| Tri et NULL | Position des NULL non documentée ici | `ASC` : NULL en premier par défaut ; `DESC` : en dernier | Rendre l'ordre explicite (`NULLS LAST`, H-34), à vérifier sur Dataiku | 3 | **fait** : `test_sort_runs_on_spark_and_warns` |
| Ordre d'une table | Une recette Sort écrit des lignes triées | Une table Delta ne garantit aucun ordre de lecture | Traduire en `ORDER BY` avec un avertissement dans l'en-tête | 3 | **fait** : `test_sort_runs_on_spark_and_warns` |
| Jointure et NULL | Comportement sur les clés NULL non vérifié | `NULL = NULL` n'est jamais vrai : aucune correspondance | Comparaison SQL standard (H-37), à vérifier sur Dataiku ; sinon générer `<=>` | 3 | **fait** : `test_join_runs_on_spark` (clé NULL non appariée) |
| Écart-type | Formule (échantillon ou population) non vérifiée | `stddev` = `stddev_samp` | Refuser `stddev` tant que la formule n'est pas confirmée (H-38) | 3 | **fait** : `test_group_never_guesses` |
| Cadre de fenêtre | Cadre par défaut non vérifié | Avec `ORDER BY` et sans cadre : du début de la partition à la ligne courante (`RANGE`) | Toujours écrire un cadre `ROWS` explicite (H-40) et l'afficher dans l'en-tête | 3 | **fait** : `tests/test_translate_window.py` |
| Division par zéro | Résultat non vérifié | En mode ANSI (défaut de Spark 4 et de Databricks SQL), erreur qui fait échouer le job | `try_divide` : NULL au lieu d'une erreur | 4 | **fait** : `test_division_by_zero_gives_null_not_an_error` |
| Division entière (SQL) | En PostgreSQL, SQL Server et Teradata, entier / entier tronque (`7 / 2 = 3`) | `/` donne toujours un décimal (`3.5`) | Signaler chaque division d'une recette SQL transpilée depuis ces dialectes (avertissement « à relire ») | 8 | **fait** : `test_integer_division_is_reported` |
| pandas → table | `write_with_schema` déduit le schéma du DataFrame pandas | `spark.createDataFrame(pandas)` le déduit aussi, mais un entier avec des valeurs manquantes devient décimal, et un objet vide n'a pas de type | Avertissement « à relire » dans chaque notebook réécrit : comparer les types écrits au schéma Dataiku ; tests d'exécution avec Arrow, comme sur Databricks | 8 | **fait** (avertissement) : `test_rewritten_recipe_runs_on_spark` |
| Comparer des flottants | Les calculs Dataiku et Spark peuvent différer au dernier chiffre (ordre des sommes, arrondis) | Une égalité stricte signale un faux écart | Tolérances absolue et relative par table (`config/reconcile.yaml`), uniquement sur les colonnes numériques et avec une clé ; comptes, NULL et distincts restent exacts | 9 | **fait** : `test_aggregate_layer`, `test_row_layer_with_key` |
| NULL dans la comparaison | — | `NULL = NULL` n'est pas vrai : deux lignes identiques avec un NULL sembleraient différentes | Comparaison `<=>` (null-safe) ligne à ligne, et `EXCEPT ALL` (qui traite deux NULL comme égaux) sans clé | 9 | **fait** : `test_null_values_compare_equal` |
